# dsh-skills-market

Плагин для веб-интерфейса [DeepSeek Harness](https://github.com/deepseek-ai): показывает
файлы `SKILL.md`, которые уже есть на машине, и ставит новые из курируемого реестра,
[SkillsMP](https://skillsmp.com), [skills.sh](https://skills.sh) и GitHub.

Формат агентских скилов кросс-платформенный — один и тот же `SKILL.md` читают DSH, Claude
Code, Cursor и Codex, — поэтому `~/.agents/skills` здесь полноценная цель установки, а не
довесок.

![Установленные скилы](preview-installed.png)

## Как это работает

Плагин — это npm-пакет из двух половин. `index.js` работает в Node как Cordis-плагин и
владеет файловой системой и сетью; `client.js` работает в браузере и владеет страницей. Они
встречаются на JSON API по пути `/dsh-skills-market`.

| Маршрут | Метод | Что отдаёт |
| --- | --- | --- |
| `/state` | GET | Просканированные корни, установленные скилы, resolved-конфиг |
| `/catalog` | GET | Курируемые карточки, при желании слитые с результатами живого поиска |
| `/skill` | GET | Один установленный скил: его `SKILL.md` и список файлов |
| `/search` | GET | Живой поиск по включённым источникам |
| `/install` | POST | Скачать скил и записать его в корень |
| `/remove` | POST | Удалить директорию установленного скила |

Любой ответ — `{ ok: true | false, ... }`. Тело запроса ограничено
`MAX_BODY_BYTES = 1_000_000`; на большее отвечает `413`.

### Корни скилов

`dsh-skill-filesystem` читает четыре корня. Плагин сканирует все четыре, а ставит в два.

| id корня | Путь | Сканируется | Установка |
| --- | --- | --- | --- |
| `user-dsh` | `$DSH_HOME/skills` | да | да |
| `user-agents` | `$DSH_AGENTS_HOME/skills`, иначе `~/.agents/skills` | да | да |
| `project-dsh` | `<projectRoot>/.dsh/skills` | да | нет |
| `project-agents` | `<projectRoot>/.agents/skills` | да | нет |

`$DSH_HOME` **не** считается равным `~/.dsh`. Управляемая установка обычно указывает его в
другое место, и маркет, пишущий в литеральный `~/.dsh`, ставил бы скилы, которые агент не
читает. Страница печатает resolved-абсолютный путь каждого просканированного корня, чтобы их
можно было сравнить, а не угадывать.

Распознаются обе раскладки — те же, что принимает `dsh-skill-filesystem`:

| Раскладка | Пример |
| --- | --- |
| Директория-бандл | `<root>/<name>/SKILL.md` |
| Плоский файл | `<root>/<name>.md` |

### Установка

1. Скачать точку входа — URL на `raw.githubusercontent.com` либо директорию GitHub, обойдённую
   через contents API.
2. Вывести имя скила из frontmatter-поля `name:`, затем из URL, затем из заголовка.
3. Создать `<root>/<name>/` и записать туда бандл.
4. Записать `SKILL.md` **последним**.

Шаг 4 и делает неудачную установку безопасной; он разобран в разделе *Почему сделано именно
так*.

Карточка из GitHub тянется целым бандлом, а не одним файлом: `SKILL.md`, который ссылается на
`rules/` или `references/`, без них сломан. Обход рекурсивный, но ограничен
`MAX_BUNDLE_DEPTH = 2`, параметром `maxSiblingFiles` и бюджетом байтов.

### Курируемый реестр

В `data/catalog.json` лежат 24 карточки, и каждая — реальный `SKILL.md`, который был скачан и
прочитан при написании карточки. `scripts/build-curated.mjs` валидирует файл и генерирует
`lib/curated-data.js`; сгенерированный модуль руками не правят.

| Репозиторий | Карточек | Категории |
| --- | --- | --- |
| `anthropics/skills` | 6 | frontend, layout, prompt, docs, testing |
| `vercel-labs/agent-skills` | 4 | frontend, layout |
| `wshobson/agents` | 9 | frontend, layout, debug, prompt, docs, testing, git |
| `obra/superpowers` | 5 | debug, prompt, testing, git |

Распределение по категориям: frontend 5, layout 5, debug 4, prompt 3, docs 3, testing 2, git 2.

Генератор **отказывается собирать карточку, у которой `raw`-URL не совпадает с её
`repo`/`branch`/`path`**. Опечатка поэтому валит сборку, а не доезжает до кнопки «Установить»,
где всплыла бы как 404 в чужом браузере.

### Живые источники

| Источник | Эндпоинт | Ключ | Состояние |
| --- | --- | --- | --- |
| `skillsmp` | `https://skillsmp.com/api/v1/skills/search` | не нужен, ключ опционален | включён по умолчанию |
| `skillssh` | `https://skills.sh/api/v1/skills/*` | Vercel OIDC token | без токена тёмный |
| `github` | GitHub code search, `filename:SKILL.md` | personal access token | включается вручную |

`DEFAULT_LIVE_SOURCES = ['skillsmp']` — единственный адаптер без credentials. Дефолт, который
всегда рисовал бы ошибку авторизации, читался бы как баг, а не как настройка.

Два провайдера отклонены по фактам, а не по вкусу:

- **AgenticSkills не подключён.** `agenticskills.com` — припаркованный домен: он
  редиректит cross-origin на маркетплейс по перепродаже доменов, а `/api/skills` и
  `/api/v1/skills` отвечают `404`. JSON API нет, разметки карточек для скрейпинга тоже, так
  что адаптер был бы вечно сломанной полкой. Тест фиксирует его отсутствие.
- **skills.sh выключен по умолчанию.** Все маршруты `/api/v1/*` отвечают
  `401 {"error":"authentication_required"}` и требуют Vercel OIDC bearer-токен. Форму ответа
  за этой стеной подтвердить не удалось, поэтому маппинг намеренно терпим к отсутствующим
  полям.

Форма API SkillsMP подтверждена — `{ success, data: { skills, pagination, filters }, meta }`,
элементы несут `id`, `name`, `author`, `description`, `contentLanguage`, `githubUrl`,
`skillUrl`, `stars`, `updatedAt`. Но **релевантность поиска сломана на стороне провайдера**:
и `q=react`, и `q=tailwind` вернули посторонние скилы. Как источник он годится, как полка для
разглядывания — нет; отсюда и курируемый реестр.

Источник, упёршийся в лимит, сообщается вместе со своим **кулдауном**, а не только кодом
состояния. SkillsMP на исчерпанную дневную квоту отвечает `429` и `Retry-After: 78860`;
страница превращает это в живой отсчёт — *повтор через 21 ч 49 мин*, — потому что `429` сам
по себе не говорит читателю, ждать секунду или сутки. Когда окно истекает, строка просит одно
обновление. Хост, не назвавший окна, не получает и часов: отсчёт, за которым ничего не стоит,
хуже голого кода.

## Что изменила композиция

Страница регистрируется **дважды**, и эти два места по-разному решают, кто даёт контейнер
прокрутки.

| Место | Регистрация | Кто прокручивает |
| --- | --- | --- |
| Боковая панель | `sidebar.panellist` (order 1) + keyed `main` (`key: 'skills-market'`) | сама страница |
| Настройки | `settings.section` (id `skills-market`, order 46) | бокс опций хоста |

Каркас боковой панели — `height:100%; overflow:hidden`, и скроллера он не даёт вообще:
страница в этом месте, не прокручивающая себя сама, просто обрезается и дальше сгиба
нечитаема. Диалог настроек прокручивает — `.VOzbGW_options { flex:1; min-height:0;
overflow-y:auto }`. Поэтому страница несёт `height:100%; overflow-y:auto` и собственные
отступы, повторяя то, что `dsh-client-ui-plugin-manager` делает для страницы Plugins.
`height:100%` резолвится против того бокса, в который страница попала, и это оставляет ровно
один скроллбар в обоих местах.

Страница также держит по одному слоту ошибки **на вкладку**. Баннер рендерится над
переключателем вкладок, поэтому ошибка без области — скажем, умершая загрузка каталога —
закрасила бы список установленного: вкладку, которая к ней отношения не имеет и не даёт
способа на неё отреагировать.

Две строки здесь несущие, а не косметические:

- **`id` у `sidebar.panellist` обязан совпадать с `key` панели `main`.** Это две половины
  одной регистрации; разойдутся — строка в сайдбаре отрисуется и ничего не откроет.
- **Кап `max-width` стоит на внутренней обёртке, а не на контейнере прокрутки.** Кап на
  скроллере вешает его скроллбар посреди широкой панели вместо края панели.

`order: 46` ставит секцию сразу под MCP-маркетом (`order: 45`).

## Установка

У плагина нет зависимостей. Его host-половина импортирует только `node:*` — это требование, а
не аккуратность: бандл, установленный в профиль, резолвит bare-спецификаторы из своего
каталога и не видит `node_modules` харнесса.

```sh
# 1. Положите этот чекаут в стабильное место и добавьте его в профиль.
cd "$DSH_PROFILE_DIR"

# package.json: в "dependencies"
#   "@local/dsh-skills-market": "link:<абсолютный путь к этому чекауту>"
# package.json: в "dsh.profile.bundles"
#   "@local/dsh-skills-market"

# 2. Материализуйте ссылку.
pnpm install

# 3. Перезапустите веб-сервер.
dsh web --port 3080
```

Правка `client.js` или `index.js` доезжает до браузера **только после перезапуска**. Хост
кэширует байты бандла в процессе и выводит ревизию артефакта из mtime/ctime/size файла; корни
наблюдения HMR включаются вручную и по умолчанию пусты (`dsh-base/cordis.patch.yml`
регистрирует `hmr` с `config: { root: [] }`). Правка конфига loader-строки тоже не
переактивирует плагин — Cordis мержит конфиг в живой инстанс. Обновление страницы отдаст
старый бандл.

## Секреты

В этом репозитории ничего не хранится, и для работы плагина не нужен ни один ключ.

| Настройка | Что при пустом значении |
| --- | --- |
| `githubToken` | GitHub code search недоступен, действует анонимный лимит API |
| `skillsmpKey` | анонимный доступ, задокументированный провайдером как 50 запросов в день |
| `skillsshToken` | источник `skillssh` отвечает `401` и остаётся тёмным |

Токены читаются из конфига самого плагина и уходят как `Authorization: Bearer <token>` в тех
запросах, где нужны. Плагин никогда не пишет их на диск и не логирует.

## Настройки

| Настройка | Допустимые значения | По умолчанию |
| --- | --- | --- |
| `enabled` | boolean | `true` |
| `defaultTarget` | `user-dsh`, `user-agents` | `user-dsh` |
| `dshHome` | абсолютный путь | `$DSH_HOME`, затем `~/.dsh` |
| `agentsHome` | абсолютный путь | `$DSH_AGENTS_HOME`, затем `~/.agents` |
| `projectRoot` | абсолютный путь | пусто — только пользовательские корни |
| `curatedUrl` | HTTPS-URL JSON-массива карточек | пусто — встроенный реестр |
| `liveSources` | через запятую: `skillsmp`, `skillssh`, `github` | `skillsmp` |
| `githubToken` | строка | пусто |
| `skillsmpKey` | строка | пусто |
| `skillsshToken` | строка | пусто |
| `allowRemote` | boolean | `false` |
| `allowInsecure` | boolean | `false` |
| `maxSiblingFiles` | целое 0–200 | `40` |

`allowRemote` выключен по умолчанию, потому что `/install` и `/remove` пишут в файловую
систему. Пока он выключен, оба маршрута отвечают `403` на любой адрес, кроме loopback.

`allowInsecure` выключен по умолчанию. Пока он выключен, `assertFetchableUrl` принимает только
`https:` и отказывает loopback-, link-local- и приватным диапазонам — `127.`, `10.`, `192.168.`,
`172.16`–`172.31`, `169.254.`, `localhost`, `::1`. Без этой проверки маркет был бы примитивом
SSRF, нацеленным на всё, до чего дотягивается хост.

## Стоимость

Открытие страницы не стоит ничего. Встроенный реестр генерируется на этапе сборки, поэтому
отрисовка каталога не делает ни одного сетевого запроса.

Живой поиск и установка в сеть ходят — в пределах лимитов провайдера:

| Провайдер | Лимит | Откуда известно |
| --- | --- | --- |
| `raw.githubusercontent.com` | не задокументирован | — |
| GitHub API | 60 запросов/час на IP анонимно, 5000 с токеном | задокументировано GitHub |
| SkillsMP | 50 запросов/день анонимно | как указано в настройке `skillsmpKey` самого плагина |
| skills.sh | все маршруты `/api/v1/*` требуют токен | измерено: `401 authentication_required` |

## Классы отказов

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `429 Too Many Requests` | квота источника исчерпана; у SkillsMP это 50 запросов в день | дождаться конца отсчёта в строке или задать ключ для этого источника |
| `401 {"error":"authentication_required"}` | `skillssh` включён без `skillsshToken` | задать токен или убрать `skillssh` из `liveSources` |
| `403` на `/install` или `/remove` | запрос с не-loopback адреса при `allowRemote: false` | открывать UI на loopback или осознанно включить `allowRemote` |
| `413` | тело запроса больше `MAX_BODY_BYTES` | отправить тело меньше |
| `response too large` | файл больше `DEFAULT_MAX_FILE_BYTES` | поднять лимит или поставить скил руками |
| `unsafe skill name` | имя не прошло `isSafeSkillName` или вышло за пределы корня | переименовать скил |
| Установка прошла, а агент скила не видит | харнесс загружает скилы при старте сессии | открыть New Session |
| Установленный скил не появляется в списке | записан в `DSH_HOME`, который харнесс не читает | сравнить resolved-путь корня, напечатанный на странице |
| Список в сайдбаре обрезан и не листается | страница потеряла свои `height:100%; overflow-y:auto` | см. *Что изменила композиция* |

## Как откатить

Уберите loader-запись и зависимость из `package.json` профиля, выполните `pnpm install` и
перезапустите `dsh web`. Плагин ничего не пишет за пределами корней скилов, так что больше
чистить нечего.

Установленные им скилы остаются на диске. Удалите их со страницы, если хотите избавиться, или
снесите директории в `$DSH_HOME/skills` и `$DSH_AGENTS_HOME/skills` напрямую.

## Почему сделано именно так

Объяснения заслуживает порядок записи, при котором `SKILL.md` пишется последним.

Установка не атомарна: плагин скачивает несколько файлов и пишет их по одному. Очевидный
порядок — сначала точка входа, потом файлы, на которые она ссылается, — оставляет директорию,
похожую на рабочий скил, ровно в тот момент, когда он наименее рабочий. Если загрузка умрёт
на середине, загрузчик увидит валидный `SKILL.md`, загрузит скил, и тот упадёт на
отсутствующем файле `rules/` уже в момент использования — далеко от причины.

Запись точки входа последней это переворачивает. Директория без `SKILL.md` для
`dsh-skill-filesystem` не скил, поэтому недописанный бандл невидим, а не сломан, — а невидимую
директорию повторная попытка может перезаписать.

Второе решение меньше, но той же формы: курируемый реестр — это **снимок на этапе сборки, а
не живой запрос**. Релевантность поиска у провайдеров вне контроля плагина — у SkillsMP она
измеримо сломана, — и каталог, молча возвращающий посторонние скилы, учит читателя не доверять
всей странице. Карточка, скачанная и прочитанная один раз, на этапе сборки, — это утверждение,
за которое репозиторий может отвечать.

## Разработка

`scripts/preview.mjs` рендерит настоящий компонент в автономный HTML-файл, чтобы раскладку
можно было посмотреть без запущенного харнесса. Он загружает фабрику ровно так, как это делает
хост, перехватывает стилевой лист, который вставляет страница, сериализует дерево элементов,
возвращённое компонентом, и тянет живые payload'ы `/state` и `/catalog`, когда сервер отвечает.
Абсолютные пути переписываются в `%DSH_HOME%` / `%USERPROFILE%`, чтобы закоммиченный скриншот
не нёс путей с машины.

```sh
node scripts/preview.mjs catalog     # или: installed
node scripts/preview.mjs installed --probe
```

`--probe` накладывает баннер с `clientHeight`, `scrollHeight` и `SCROLLABLE`. Статичный
снимок не отличает обрезанный бокс от прокручиваемого, поэтому без баннера сломанный
контейнер прокрутки и рабочий дают одинаковый скриншот.

Токены хоста `--dsw-alias-*` вне харнесса не определены, поэтому превью подставляет их тёмную
аппроксимацию. Отличаются только значения; каждое проверяемое правило — то самое, что
поставляется. А вот привязка локали настоящая: привязать `t` к тождественной функции значило бы
напечатать в скриншот имена ключей — `secCurated`, `unitHour`, — которые читатель принял бы за
поставляемый интерфейс.
